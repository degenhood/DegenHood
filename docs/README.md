# Documentation

Public documentation is organised around the questions a reviewer or integrator needs answered.

## Protocol

- [`deployments.md`](deployments.md) — canonical addresses, chain identity and reconciliation record
- [`degenetics.md`](degenetics.md) — backed-pack economics, deployed graph and trust boundaries
- `economics.md` — supply, liquidity, fee and alignment flows with worked examples
- `authorities.md` — every role, power, transfer path, pause and irreversible action
- `launchhub.md` — launch lifecycle and active production templates
- `degen.md` — `$DEGEN`, activation, escrow and reward-pool mechanics

## Build and integrate

- `sdk.md` — unsigned preparation and verification flow
- `cli.md` — command reference and simulation
- `api.md` — HTTP authentication and OpenAPI examples
- `verification.md` — rebuild, runtime comparison and release-manifest checks

## Assurance

- [`../DUE_DILIGENCE.md`](../DUE_DILIGENCE.md) — evidence map and residual risk
- [`../SECURITY.md`](../SECURITY.md) — reporting and safe research
- `reviews.md` — public review scopes, commits, reviewers and dispositions
- `changelog.md` — material production and public-snapshot changes

Documents should answer one question well. Historical operator notes, prompts, internal handoffs and
raw review work product do not belong in this tree.
